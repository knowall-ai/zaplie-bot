= Troubleshooting Guide

[cols="2,3"]
|===
| Problem | Solution

| Bot does not respond in Teams (local)
| Check the dev tunnel is running on port 3978 and that `BOT_ENDPOINT`/`BOT_DOMAIN` in `env/.env.local` match the tunnel URL; re-run `teamsapp provision --env local`

| `412` errors logged by the bot
| Normal during the Teams SSO consent flow — the adapter deliberately swallows these; only investigate if sign-in never completes

| MSAL / `@azure/msal-node` errors on Node 20
| Add `"overrides": { "@azure/msal-node": "^2.6.0" }` to `package.json` (see README.md), or use Node 18

| Users have no wallets / "Failed Receivers" when sending a Zap
| The recipient is not in the Zaplie directory yet (they never messaged the bot or signed in to the portal), or has not registered where they receive. The card names them as "has not set up where they receive zaps yet": ask them to add their Lightning address or Private wallet invoice key on the portal's Wallet page. A sender told "Your Allowance wallet has not been set up yet" needs an admin to link one (Settings → People and Allowance wallets) or `LNBITS_API_TOKEN` configured; see `docs/LNBITS_MIGRATION.adoc`

| Every LNbits call fails after the LNbits 1.7 upgrade (`two_factor_required`)
| Zaplie no longer logs in to LNbits; a build that still sets `LNBITS_USERNAME`/`LNBITS_PASSWORD` predates `docs/LNBITS_MIGRATION.adoc`. Deploy the current build and follow the runbook. A 401/403 from LNbits now means a wallet key or `LNBITS_API_TOKEN` was refused: check the key in LNbits and, for the token, its ACL scopes

| Every zap fails with the generic "D'oh!" error after a restart
| A ledger lock is still held. Check the bot's startup log: `Zap ledger lock ... was <n>s old at startup and has been removed as crash-left` means it recovered on its own (reconcile any `processing` or `unknown` record the next line counts); `Zap ledger lock ... is <n>s old and may belong to a live process; leaving it` means the lock was younger than `ZAPLIE_LEDGER_STALE_LOCK_MS` (default 30 s) at boot. Restart the bot once more after 30 seconds, or follow the lock recovery procedure in `docs/DEPLOYMENT.adoc` (Persistent application state). Never delete `bot-zap-ledger.json` or a record in it to make zaps work again

| `send zap` card submits but payment fails
| Check `LNBITS_ADMINKEY` and `LNBITS_NODE_URL`; confirm the sender's Allowance wallet has sufficient balance and the LNbits instance is reachable from the bot

| Tabs show a blank page or bounce to `/login`
| `acquireTokenSilent` failed — verify `REACT_APP_AAD_CLIENT_ID` / `REACT_APP_TENANT_ID` and that the redirect URI `<origin>/auth-end` is registered on the AAD app

| Tab fails in Teams because a public page tried to connect to the local network
| Chrome and Edge block `teams.microsoft.com` from framing `localhost`. Use the normal F5 debug session: `Start tab` launches the tab dev server, then the tunnel task forwards port 3000 and writes `TAB_ENDPOINT` and `TAB_DOMAIN`, which the Entra and Teams manifests consume. Do not point the Teams manifest directly at `localhost`

| `Validate prerequisites` reports port 3000 is occupied
| The F5 chain starts the tab server itself (`Start tab`), so port 3000 must be free beforehand — stop any tab server you started by hand. The check is deliberate: the tunnel is public, and it must publish this project rather than whatever else was listening

| Values containing `#` or `$` are truncated when read from a `.env` file
| `#` starts a comment and CRA expands `$`. Quote the complete value in `env/.env.*`; in `tabs/.env.development`, escape a literal `$` as `\$`

| Reward name does not load / defaults to "Sats"
| The Express backend (`tabs/backend/server.js`, port 5000) is not running, or `WEBSITE_API_URL` (bot side) points to the wrong host

| Jest fails at the repo root
| Expected — the root `test` script is unwired and `jest.config.ts` has no ts-jest transform; run `npx jest src/services/lnbitsService.test.ts` directly

| PDF docs fail to build
| Install the toolchain: `gem install asciidoctor-pdf asciidoctor-diagram` and `npm i -g @mermaid-js/mermaid-cli`; then run `bash docs/generate-docs.sh`

| Mermaid diagrams fail rendering in the PDF on Ubuntu 23.10+
| The build script passes `docs/puppeteer-config.json` (`--no-sandbox`); ensure it is present and Chromium is installed for puppeteer
|===
